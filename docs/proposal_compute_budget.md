# API 및 GPU 관련 예상 소요 규모

제4회 인공지능 신약개발 경진대회 · 팀 Formula 1
대상 시스템: https://zihwan.com/formula1 (상시 가동 중)

> 제출본 원본은 `~/Downloads/Formula1_API_GPU_소요규모.md`. 수치를 고칠 때 두 곳을 같이 고친다.
> 실측 근거: RDKit 0.02초/건, 파드 RSS 155MB, Groq TPM 12k·8k·6k, 대체값 4→0건·240→123초.

## 연산이 몰리는 곳과 그렇지 않은 곳

이 시스템은 무거운 연산이 필요한 부분과 그렇지 않은 부분이 비교적 뚜렷하게 갈린다. 처방을
상상하고 연구자의 문장을 해석하는 일은 언어모델이 맡지만, 배합 금기나 규제 상한 같은 판정은
출처가 확인된 규칙표를 정해진 순서로 실행하는 결정론 연산이 담당한다. 분자 구조를 다루는
계산도 RDKit이 CPU에서 처리한다. 그래서 판정의 신뢰도를 좌우하는 계층에는 GPU가 개입할
여지가 없고, 실제로 현재 운영 중인 구성에서 GPU는 한 장도 쓰지 않는다.

## API 활용 규모와 용도

설계 한 번을 처음부터 끝까지 돌리면 언어모델을 여덟 번에서 열두 번 정도 호출한다. 자연어
요구를 정량 스펙으로 옮기는 데 한 번, 서로 다른 전략의 후보 처방을 만드는 데 두세 번(병렬),
소집된 심사관마다 평가와 점수 추출로 두 번씩, 반려가 나면 재설계 지시에 최대 다섯 번까지
쓴다. 실험 노트를 읽고 다음 시험을 정하는 단계에서 두 번이 더 붙는다. 응답 길이는 대체로
1,200 토큰 이하로 묶었고, 심사 점수만 뽑아내는 짧은 호출은 400 토큰까지 줄였다. 이렇게
해서 실행 한 번에 오가는 토큰은 대략 12,000에서 18,000 사이가 된다.

주목할 점은 이른바 도구 호출(tool calling)을 모델에 맡기지 않는다는 것이다. 규칙 검사와 근거
판정, 확인시험 후보를 추리는 일은 모두 서버가 결정론으로 먼저 처리하고, 모델에는 이미 좁혀진
선택지만 넘긴다. 모델이 목록에 없는 시험 번호를 만들어 내면 화면에 나가기 전에 버려진다.
덕분에 도구 호출을 주고받느라 토큰이 예측 불가능하게 불어나는 일이 없고, 실행 시간도
일정하게 유지된다.

외부 데이터는 PubChem에서 화합물 식별 정보를, Europe PMC에서 제형·안정성 문헌을 가져온다.
둘 다 공개 API여서 인증 키도 비용도 들지 않으며, 실행당 각각 한두 번 조회한다. 응답이 없으면
자료가 없다고 표시하고 그대로 진행한다.

운영에서 실제로 부딪힌 제약도 적어 둔다. 현재 쓰는 무료 티어는 응답 길이 상한(max_tokens)까지
분당 토큰 한도에 포함해 계산하기 때문에, 병렬로 나간 호출이 한도를 동시에 때리면 요청이
거절되고 규칙 기반 대체값으로 내려간다. 이를 막기 위해 클라이언트가 모델별 분당 한도(각각
12,000·8,000·6,000, 합계 약 26,000)를 직접 회계하고 여유가 있는 모델에 순번을 배정하도록
했다. 그 결과 대체값이 네 건에서 0건으로 줄었고, 실행 시간도 240초에서 123초로 짧아졌다.
비용 측면에서는 지금 무료 티어로 운영하므로 API 비용이 발생하지 않으며, 일반적인 상용 API
단가로 환산하더라도 실행당 0.05~0.09달러, 월 3,000회를 가정하면 150~270달러 수준이다.

## GPU 자원 소요

규칙 게이트와 근거 충족 게이트는 조건식을 평가하는 순수 파이썬 코드라 실행당 수십 밀리초면
끝난다. 분자 기술자 44종과 구조 패턴 82종을 계산하고 2차원 구조를 그리는 RDKit 작업은
분자 한 건에 0.02초가 걸렸다. 문헌 검색은 임베딩 모델 없이 BM25 방식을 쓰므로 역시 CPU로
충분하다. 결국 현재 구성에서 GPU가 필요한 지점은 없다.

GPU가 필요해지는 경우는 물성 예측 모델을 연결할 때다. 용해도·투과도·pKa 예측기(ADMET-AI,
SolTranNet, QupKake)를 붙일 자리와 교차검증 로직은 이미 만들어 두었고, 세 모델 모두 공개된
사전학습 가중치를 그대로 쓰는 추론 전용이라 별도의 학습 계획은 없다. 16GB 정도의 VRAM을 가진
그래픽카드 한 장이면 충분하고, 분자 한 건당 추론은 수백 밀리초 수준이어서 하루 GPU 점유
시간은 몇 분에 그칠 것으로 본다. 현재는 예측기를 연결하지 않은 상태이며, 그 사실 자체가
"예측값이 없으니 실험 용해도를 먼저 확인하라"는 요구로 판정에 반영되고 있다.

외부 API 의존을 없애기 위해 언어모델을 직접 서빙하는 선택지도 있다. 70B급 모델을 4비트로
양자화하면 A100 40GB 또는 L40S 48GB 한 장으로 동시 3건 정도의 부하를 감당할 수 있다. 다만
이 시스템에서 언어모델은 처방을 반려할 권한이 없는 계층이므로, 자체 서빙은 비용과 응답
속도의 문제이지 판정의 신뢰도와는 무관하다는 점을 덧붙인다.

## 현재 운영 환경

애플 실리콘 맥 한 대를 24시간 홈서버로 돌리고, 쿠버네티스 파드 하나가 단일 워커로 서비스를
제공한다. 파드의 상주 메모리는 약 155MB이고 CPU는 실행 중에만 한 코어 정도를 쓴다. 공개
서비스이므로 동시 실행 3건, 실행 기록 보관 40건으로 스스로 제한하고, 앞단에서 IP당 5분에
12회로 요청을 묶어 둔다. 추가 인프라 비용 없이 유지되고 있으며 심사 기간에도 같은 조건으로
접속할 수 있다.

## 정리

이 시스템에서 판정의 신뢰도는 GPU 규모가 아니라 규칙표와 근거 정책에서 나온다. 자원을 늘린다고
판정이 정확해지지 않고, 자원이 없다고 판정이 나빠지지도 않는다. GPU가 실제로 필요한 곳은 물성
예측 한 군데이며 추론 전용 16GB 한 장이면 되고, 언어모델 API는 지금처럼 무료 티어로 감당할 수
있되 유료로 전환하더라도 월 수백 달러 규모다. 앞으로 확장에 드는 비용의 대부분은 연산이 아니라
규칙표와 확인시험 항목을 넓히는 데, 즉 약학 데이터를 쌓는 데 들어갈 것으로 예상한다.
