# API 및 GPU 관련 예상 소요 규모

**과제명** 실패를 미리 겪어보는 AI 제형 설계 시스템 (Formula 1)
**작성 기준** 상시 가동 중인 실서비스(https://zihwan.com/formula1) 실측치

> 저장소 사본. 제출본은 `~/Downloads/Formula1_제안서_API_GPU_소요규모.md` — 수치를 고치면 두 곳을 같이 고친다.

---

## 1. 산정 개요

본 시스템은 **생성·해석 계층(LLM)** 과 **판정 계층(결정론적 규칙 연산)** 이 분리된 구조를 갖는다.
처방 후보 생성과 자연어 해석은 LLM 추론 API가 담당하고, 배합 금기·공정·규제 판정은 출처가
검증된 규칙표를 우선순위에 따라 실행하는 CPU 연산이 담당한다. 이러한 권한 분리에 따라
자원 소요는 **LLM API 호출량에 집중**되며, **GPU는 현행 구성에서 소요가 발생하지 않는다.**

아래 산정치는 추정이 아니라 상시 가동 중인 서비스에서 측정한 값을 근거로 한다.

---

## 2. API 활용 규모 및 용도

### 2.1 LLM 추론 엔진 적용 범위

LLM은 창의적 생성과 자연어 해석에 한정하여 적용하며, 안전성·규제 판정에는 적용하지 않는다.
전 호출을 구조화 출력(JSON Schema) 방식으로 수행하여 파싱 실패 요인을 제거하였다.

| 적용 기능 | 용도 | 실행당 호출 | 응답 상한 |
|---|---|---|---|
| 요구 해석(intake) | 자연어 요구 → 정량 스펙 변환 | 1회 | 1,200 tok |
| 후보 생성 | 공정 전략별 처방 후보 병렬 설계 | 2~3회 | 1,200 tok |
| 심사 평가 | 동적 소집 심사 에이전트의 정성 평가·점수 산출 | 소집 인원 × 2회 | 600 / 400 tok |
| 반성·재설계 | 반려 사유 분석 및 개선 지시 (상한 5회) | 0~5회 | 1,200 tok |
| 실험 결과 판독 | 실험 노트 자연어 → 측정값 전사 | 1회 | 1,200 tok |
| 후속 시험 선정 | 확인시험 66종 내 차기 시험 결정 | 1회 | 1,200 tok |

### 2.2 도구 호출(Tool Calling) 처리 방식

외부 도구 호출을 LLM에 위임하지 않고, 서버가 결정론적으로 선행 처리한 후 축소된 후보만을
모델에 전달하는 방식을 채택하였다. 규칙 검사, 근거 충족 판정, 확인시험 후보 선별이 모두
서버 측에서 이루어지며, 모델이 허용 목록 외 시험 식별자를 반환할 경우 출력 단계에서 폐기된다.
그 결과 도구 호출 왕복이 발생하지 않아 **토큰 사용량과 응답 지연이 예측 가능한 범위 내에서
유지**된다.

### 2.3 외부 데이터 API

PubChem(화합물 식별 정보·보고 물성)과 Europe PMC(제형·안정성 문헌)를 실행당 각 1~2회
조회한다. 양자 모두 공개 API로 인증 키 및 이용료가 발생하지 않으며, 조회 결과가 없는 경우
자료 부재를 명시하고 후속 절차를 진행한다.

### 2.4 소요 규모 산정

| 구분 | 산정치 | 산정 근거 |
|---|---|---|
| 단위 실행당 호출 | 8~12회 | 2.1 기능별 호출 합산 |
| 단위 실행당 토큰 | 12,000~18,000 tok | 프롬프트 + 응답 상한 기준 |
| 일 소요 (200 실행 가정) | 약 3M tok/일 | 시연·심사 기간 최대 부하 |
| 월 소요 | 약 90M tok/월 | 상기 일 소요 × 30일 |
| 현행 비용 | **0원** | 무료 티어 운영 |
| 유료 전환 시 비용 | 실행당 0.05~0.09 USD<br>월 150~270 USD (3,000 실행 기준) | 상용 API 단가 환산 |

### 2.5 처리량 제약 및 대응 실적

현행 무료 티어는 응답 상한(`max_tokens`) 예약분을 분당 토큰 한도(TPM)에 합산하여 계산하므로,
병렬 호출이 한도에 동시 도달할 경우 요청이 거절되고 규칙 기반 대체값으로 전환되는 문제가
확인되었다. 이에 대응하여 모델별 TPM(12,000 / 8,000 / 6,000, 합계 약 26,000)을 클라이언트
측에서 회계하고 잔여 예산이 있는 모델에 순차 배정하는 방식을 적용하였다.

- 적용 전: 대체값 4건 발생, 실행 시간 240초
- 적용 후: **대체값 0건, 실행 시간 123초**

## 3. GPU 자원 소요 규모

### 3.1 현행 소요 — **0장**

판정 계층 전체가 CPU 연산으로 처리되어 GPU 소요가 발생하지 않는다. 산정 근거는 다음과 같다.

- 규칙 게이트(규칙표 27종·검사 함수 8개) 및 근거 충족 게이트(요구 16종): 조건식 평가, 실행당 수십 ms
- RDKit 분자 연산(기술자 44종·구조 패턴 82종·2D 렌더링): **분자 1건당 0.02초** (실측)
- 문헌 검색: BM25 희소 검색 방식으로 임베딩 모델 미사용

### 3.2 확장 시 소요 — **추론 전용 GPU 1장 (VRAM 16GB급)**

물성 예측 모델(ADMET-AI, SolTranNet, QupKake) 연결 시 GPU 추론이 필요하다. 3개 모델 모두
공개된 사전학습 가중치를 활용하는 **추론 전용**이며 별도의 학습 계획은 없다.

- 권장 사양: T4 / L4 / RTX 4000급 (VRAM 16GB)
- 처리 성능: 분자 1건당 수백 ms, 배치 처리 시 일 GPU 점유 수 분 이내
- 현황: 미연결 상태이며, 미연결 사실 자체가 "실험 용해도 선행 확보" 요구로 판정에 반영됨

### 3.3 선택적 확장 — LLM 자체 서빙 시 **GPU 1장 (VRAM 40~48GB급)**

외부 API 의존도 제거를 위해 자체 서빙을 검토할 경우, 70B급 모델 4bit 양자화 기준
A100 40GB 또는 L40S 48GB 1장으로 동시 3건 처리가 가능하다. 다만 본 구조에서 LLM은 처방
반려 권한이 없는 계층이므로, 자체 서빙은 판정 신뢰도가 아닌 **비용·응답 지연 최적화** 목적에
해당한다.

## 4. 운영 인프라 현황

Apple Silicon 1대를 24시간 가동하여 Kubernetes 파드 1개(단일 워커)로 서비스를 제공한다.
파드 상주 메모리는 **약 155MB**(실측), CPU는 실행 구간에 한하여 1코어 수준을 점유한다.
공개 서비스 특성상 동시 실행 3건·실행 기록 보관 40건으로 자체 제한하고, 전단에서 IP당
5분 12회로 요청을 제한한다. **추가 인프라 비용 없이 상시 운영 중이며, 심사 기간 중에도
동일 조건으로 접속 가능하다.**

## 5. 종합

| 자원 | 현행 | 확장 시 (예측 모델 연결) | 비고 |
|---|---|---|---|
| LLM API | 무료 티어 / 월 최대 90M tok | 동일 | 유료 전환 시 월 150~270 USD |
| GPU | 0장 | 추론 전용 1장 (16GB) | 학습 없음, 일 점유 수 분 |
| 외부 데이터 API | PubChem·Europe PMC | 동일 | 인증키·비용 없음 |
| 서버 | 파드 1개 / RSS 155MB | 동일 | 추가 비용 없음 |

본 시스템의 판정 신뢰도는 연산 자원의 규모가 아니라 **규칙표의 근거 품질과 근거 충족 정책**에서
확보된다. 따라서 자원 증설이 판정 정확도를 향상시키지 않으며, 자원 제약이 판정 품질을 저하시키지
않는다. GPU 소요는 물성 예측 계층 1개소에 한정되고 추론 전용 16GB 1장으로 충족 가능하며,
향후 확장 비용의 대부분은 연산 자원이 아니라 **규칙표·확인시험 항목 등 약학 데이터 확충**에
투입될 것으로 예상한다.
