# API 및 GPU 관련 예상 소요 규모

> 제4회 인공지능 신약개발 경진대회 · 팀 **Formula 1** 제안서 첨부
> 기준 시스템: `https://zihwan.com/formula1` (2026-08 기준 상시 가동본)

## 1. 요약

| 항목 | 현재 (상시 가동본) | 심사·시연 기간 | 확장 시나리오 (예측 모델 연결) |
|---|---|---|---|
| LLM API | Groq 무료 티어, 실행당 **8~12회 호출** | 동일 (동시 3건 상한) | 동일 |
| 토큰 | 실행당 **약 12~18k tokens** | 일 200 실행 시 **약 3M tokens/일** | 동일 |
| GPU | **0장** (전 계층 CPU) | 0장 | 추론 전용 **GPU 1장**(16GB급) |
| 외부 도구 API | PubChem·Europe PMC (키 불필요) | 동일 | 동일 |
| 실행 시간 | 설계 1회 **약 60~123초** | 동일 | +5~15초 (예측 추론) |

핵심은 **판정 계층이 GPU를 쓰지 않는다**는 점이다. 안전·규제 판정은 규칙표를 순서대로 실행하는
결정론 연산이고, 분자 구조 계산은 RDKit(CPU)이다. GPU는 물성 **예측 모델**을 연결할 때만
필요하며, 그것도 학습이 아니라 추론 전용이다.

## 2. LLM API — 활용 규모와 용도

LLM은 **창의·해석 계층에만** 쓰인다. 호출은 전부 구조화 출력(JSON 스키마)이라 파싱 실패가 없다.

| 노드 | 용도 | 실행당 호출 | 응답 상한 |
|---|---|---|---|
| intake | 자연어 요구 → 정량 스펙 번역 (물성 수치는 지어내지 않음) | 1 | 1,200 tok |
| generate | 전략별 처방 후보 설계 (직접타정·습식과립·가용화) | 2~3 (병렬) | 1,200 tok |
| judge | 소집된 심사관의 정성 평가 + 점수 추출 | 소집 인원 × 2 | 600 / 400 tok |
| reflect | 반려 사유 분석 → 재설계 지시 (최대 5회) | 0~5 | 1,200 tok |
| labloop.read | 실험 노트 판독 (문장에 적힌 수치만 전사) | 1 | 1,200 tok |
| labloop.direct | 다음 확인시험 선정 (66종 안에서만 선택) | 1 | 1,200 tok |

**도구 호출(tool calling)은 LLM에 위임하지 않는다.** 규칙 검사·근거 판정·확인시험 후보 필터링은
서버가 결정론으로 수행하고, 모델에는 이미 좁혀진 후보만 전달한다. 모델이 목록 밖 `test_id`를
반환하면 화면에 나가기 전에 폐기된다 — 이 구조 때문에 도구 호출 왕복이 발생하지 않아
토큰과 지연이 예측 가능하다.

**외부 데이터 API**: PubChem(화합물 식별·물성)과 Europe PMC(제형·안정성 문헌)를 실행당 각
1~2회 조회한다. 둘 다 공개 API로 인증 키·비용이 없고, 응답이 없으면 "자료 없음"으로 표시하고 진행한다.

**분당 토큰 한도(TPM) 회계**: 무료 티어에서는 `max_tokens` 예약분도 한도에 포함되므로, 병렬
팬아웃이 한도를 동시에 때리면 호출이 거절되고 규칙 기반 대체값으로 내려간다. 이를 막기 위해
클라이언트가 모델별 TPM(12k/8k/6k, 합계 약 26k)을 직접 회계하고 예산이 있는 모델에 순번을
배정한다. 실측 결과 대체값 4건 → **0건**, 실행 시간 240초 → **123초**로 개선됐다.

**유료 전환 시 비용**: 실행당 약 15k tokens 기준, 상용 API(입력 $3 / 출력 $15 per M tokens 급)로
환산하면 **실행당 약 0.05~0.09 USD**, 월 3,000 실행 시 **약 150~270 USD** 수준이다.
현재는 무료 티어로 운영하므로 API 비용은 0이다.

## 3. GPU 자원 소요

| 구성 요소 | 연산 | GPU 필요 | 근거 |
|---|---|---|---|
| 규칙 게이트 (규칙표 27종·검사 함수 8개) | 조건식 평가 | 불필요 | 순수 파이썬, 실행당 수십 ms |
| 근거 충족 게이트 (요구 16종) | 조건식 평가 | 불필요 | 동일 |
| RDKit 계층 (기술자 44종·SMARTS 82종·2D 렌더) | CPU 벡터 연산 | 불필요 | 분자 1건 **0.02초** (실측) |
| RAG (BM25, 문서 2,083개) | 희소 검색 | 불필요 | 임베딩 모델 미사용 |
| LLM 추론 | 외부 API | 불필요 (자체 서빙 시 필요) | 아래 참조 |
| 물성 예측 모델 | GNN 추론 | **필요 (확장 시)** | 아래 참조 |

**확장 시나리오 ①  물성 예측 모델 연결.** 용해도·투과도·pKa 예측기(ADMET-AI, SolTranNet,
QupKake)를 붙이면 GPU 추론이 필요하다. 세 모델 모두 **사전학습 가중치를 그대로 쓰는 추론
전용**이며 학습 계획은 없다. 소요는 **16GB VRAM 1장**(T4·L4·RTX 4000급)으로 충분하고,
분자 1건당 추론은 수백 ms 수준이다. 배치 처리 시 GPU 점유는 하루 수 분에 그친다.
현재는 미연결 상태이며, 그 사실 자체가 "예측값 없음 → 실험 용해도 선행 요구"로 판정에 반영된다.

**확장 시나리오 ②  LLM 자체 서빙(선택).** 외부 API 의존을 없애려면 70B급 모델을 4bit 양자화해
**A100 40GB 1장** 또는 **L40S 48GB 1장**으로 서빙할 수 있다. 동시 3건·평균 1,200 토큰 응답
기준으로 1장이면 대회 시연 부하를 감당한다. 다만 현재 구조에서 LLM은 **반려 권한이 없는**
계층이므로, 자체 서빙은 비용·지연 최적화 문제이지 판정 신뢰도와는 무관하다.

## 4. 상시 가동 인프라 (현재)

Apple Silicon 맥 1대를 24시간 홈서버로 운영하며, Kubernetes 파드 1개(단일 워커)로 서빙한다.
동시 실행 3건·보관 40건으로 자체 제한하고, 앞단에서 IP당 5분 12회로 요청을 제한한다.
파드의 상주 메모리는 **약 155MB**(실측), CPU는 실행 중에만 1코어 수준이다. **추가 인프라 비용 없이
공개 서비스가 유지되고 있으며**, 심사 기간에도 같은 조건으로 접속 가능하다.

## 5. 요약 판단

- 이 시스템의 **판정 신뢰도는 GPU 규모가 아니라 규칙표와 근거 정책에서 나온다.** 따라서 자원을
  늘려도 판정이 좋아지지 않고, 자원이 없어도 판정이 나빠지지 않는다.
- GPU가 필요한 부분은 물성 예측 한 곳이며, **추론 전용 16GB 1장**이면 충분하다.
- LLM API는 무료 티어로 운영 중이고, 유료 전환하더라도 월 수백 달러 규모다.
- 확장 비용의 대부분은 연산이 아니라 **약학 데이터(규칙표·근거 요구·확인시험) 확충**에 든다.
