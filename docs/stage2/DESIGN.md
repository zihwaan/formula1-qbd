# 2단계 — Design Space 도출 (구현 설계)

> 기준: 사용자 제공 `2단계_수정본.pptx`(슬라이드 1–12)와 그 가이드, `Formula1_본선발표`(PDF 판) 5·6·9·10·13쪽
> (Stage I → [이 후보로 개발 착수] → Stage II: QTPP → CQA → Risk 평가 → DoE toolkit → Design Space → 확인계획),
> 10·13단계 = 사용자 제공 overlay 파이프라인(`overlay_pipeline.zip` — 07_model_selection · 08_design_space, 검증 게이트 표 · 13단계 승인 불가 조건 표),
> Monton 2026(Scientifica 2026:3553253) Table 1·3–11, Almotairi 2022(Pharmaceuticals 15:1463) Table 3.

## 범위
- **1단계(후보 탐색)는 그대로 둔다.** 통과 후보 카드의 **[이 후보로 개발 착수]**가 2단계를 연다(1위 자동 진입 없음).
  조성·공정과 요청 맥락(대상 환자·용량·제형·약물 함량·1단계 신호)은 **불변 Handoff**(fingerprint)로 넘어가고, 2단계의 LLM 초안이 함께 읽는다.
- **입구 = 근거 결손 게이트**(발표 자료 ⑤, `formula/evidence/gate.py` · `evidence_requirements.csv` 16행 · 확인시험 마스터 66종). 통과 후보마다
  선행(before_protocol) 근거가 있는지 결정론으로 판정한다(`/api/runs/{id}/evidence`). 후보 카드에는 상태 한 줄만, 입력은 후보 카드 다음의
  **근거 결손 게이트 카드 하나**(통과 후보들의 결손을 요구 항목별로 묶음 — 측정값은 스펙에 들어가 모든 후보를 함께 다시 판정)에서, 적합/부적합이 아니라 측정값으로 넣는다 —
  `POST /api/runs/{id}/measurements`(source `evidence`)로 가서 phase_gates부터 재계산 → 통과 후보 규칙 게이트 재판정 → 근거 재판정(트레이스 기록).
  값은 입력 에이전트에 말로 넣어도 된다(source `agent_evidence`) — 관측(값·단위·pH·방법)만 LLM이 뽑고, 단위 환산·pH 1.2–6.8 최저값·용량/용해도 부피·
  투과도 해석(BA·요중 회수율 ≥ 85 %만 흡수율, Papp 환산 없음)은 `formula/agents/evidence_values.py`가 ICH M9대로 계산한다.
  선행 결손이 남았으면 연구자 사유(`evidence_waiver`)가 있어야 착수한다(없으면 409 `EVIDENCE_GAPS`).
  판정·남은 결손·사유는 Handoff에 들어가 지문에 포함되고, LLM 초안 맥락("근거 결손(확인 전)")과 최종 보고서에도 실린다. 반려 권한은 여전히 룰북에만 있다.
- **논문은 참고 자료이지 정답지가 아니다.** 위험 등급처럼 판단인 칸은 논문과 달라도 오답이 아니라 검토 지점(화면: "참고 · 논문의 판단")이고,
  회귀·ANOVA·영역처럼 계산인 값만 같은 원자료에서 같은 결과가 나오는지를 테스트로 고정한다.
- v6.1 개발 스튜디오와 v7 DoE 실험개발은 삭제했다. 2단계는 이 흐름 하나로 간다.
- 화면은 대화 하나(가운데 입력 에이전트 → 카드가 아래로 쌓임, 오른쪽 관측 칼럼). 모양은 지환닷컴 공용 흑백 디자인 그대로다.

## 원칙
- LLM 초안은 판정이 아니다. 단계마다 연구자가 고치고 승인해야 다음으로 간다. LLM 응답이 없으면 아무것도 채우지 않는다.
- 결정론 검사: 4·6의 근거는 (변수 × 확정 CQA) 모든 칸을 정확히 한 번씩 덮어야 하고, 5·7 행렬은 그 근거에서 코드가 만든다(따로 입력하지 않음 → 불일치가 생길 수 없다).
  6은 처방의 모든 부형제를 평가해야 하고, 공정 이름(direct_compression 등)을 공정 변수로 쓰면 막는다.
  약물 함량 < 5 %(RTE008)인데 혼합 공정 × 함량균일성이 High가 아니면 경고한다.
- 8의 DoE 변수 후보는 제형·공정 변수 중 **하나 이상의 CQA에 High**인 것(Medium만 있는 변수는 관리·모니터링 대상으로 따로 보인다). **고르는 단계가 아니다**(사용자 결정, 2026-09-28) —
  어떤 변수를 요인으로 실험할지는 9단계 표에서 연구자가 적는다. 8단계는 코드가 만든 정리라 확인만 하고, 위험평가 보고서는 8단계에 들어오면 바로 나온다.
- 10은 **Automatic Hierarchical Model Selector → Model Validation Gate**(규칙 숫자는 `config/stage2_design_space.yaml`): 후보를 AICc로 줄 세우고
  (최소 + 2 이내면 항 수가 적은 쪽 먼저, 축소 2차 = 2차에서 계층성을 지키며 p > 0.05 항을 p 큰 순으로 제거), 게이트 — 모형 p < 0.05 · 적합결여 p ≥ 0.05
  (계산 불가면 건너뜀) · 조정 R² − 예측 R² ≤ 0.2 · 예측 R² > 0 — 를 처음 넘는 모형을 채택. 평균까지 내려가면 **요인으로 설명되지 않음**(영역·ANOVA에서 빠지고
  관측 범위와 목표만 표시). 연구자가 고른 모형도 게이트를 넘어야 쓰이고, **모든 반응이 불합격이면 승인 불가**(REG_GATE_NONE, 사용자 결정 2026-09-28).
  실험 표가 모형 차수를 보고한 논문 표(Monton 2026 Table 9)면 **논문 식으로 설정**(Table 10 모형 차수 — `paper_designs.families`, 액션 use_reference)이 열린다.
- 11은 게이트 통과 반응이 **하나라도 있으면 모든 반응의 곡면**을 그린다(사용자 결정 2026-09-29). 불합격 반응은 “검증 게이트 불합격 — 참고”(평균 모형이면 평면)로 표시하고
  영역·ANOVA에는 쓰지 않는다.
- 12의 ANOVA는 선택 모형의 부분(Type III) 제곱합, 잔차 = 적합결여 + 순수오차(같은 설정의 반복 run).
- 13은 **Overlay plot**(overlay 파이프라인 · 논문 Figure 2 형식): 게이트 통과 반응의 **평균 예측**이 모든 목표를 만족하는 격자(노랑, 축마다 41점) ∩ 설계점 convex hull.
  요인 3개면 효과(|주효과 계수| 합)가 가장 작은 요인을 −1 · 0 · +1에 고정한 세 단면(연구자가 바꿀 수 있음). control space = 단면마다 노랑에 들어가는 가장 넓은 축 정렬 직사각형
  (가로·세로 3칸 이상) 중 가장 넓은 것, 최적 처방 = 그 안에서 hull 경계로부터 0.1 coded 이상인 점 중 새 배치 통과확률(t 예측분포, 척도 √(SE² + 잔차분산), 반응별 곱)이 최대.
  이 확률은 **보조**(등고선 · 경고)이고 승인 조건이 아니다. **승인 불가는 평균 기준 영역 없음 · control space 없음 두 경우뿐**(사용자 결정 2026-09-28).
  게이트 불합격 반응은 평균 모형 95 % 예측구간이 목표에 걸치거나 목표 밖 run이 있으면 경고(막지 않음).
- 14는 결과를 보기 전에 잠근다(시각 · 해시). 다시 열면 잠금이 풀리고 15는 “다시 확인 필요”가 된다. 참고 배치(예: 논문 최적)는 승격·무효화 근거가 아니다.
- 15는 필수 3점 × 규격 반응 모두 (규격 통과 · 예측구간 안)이어야 VERIFIED(내부 사전계획 통과 — 규제 승인 설계공간이 아니다). 모형 적합에 쓰지 않은 새 독립 배치여야 한다.

    축소 2차가 조정 − 예측 R² 0.35로 불합격). 논문 규격(경도 4–6 kgf · 붕해 ≤ 30 s · 마손도 ≤ 1 %)에서 CCS 3 % 단면 control space Force 1250–1425 × MCC 30–44.5,
    최적 1312.5 · 35.5 · 3(새 배치 통과확률 0.883 — 경고만), 단면별 영역 57.2 / 48.1 / 37.7 % → 승인.

    마손도 ≤ 1 % · DE30 ≥ 75 %(가정) · AV ≤ 15)에서 혼합 시간 단면, 10분 단면 control space MCC:만니톨 1.1–3.0 × 크로스포비돈 4.6–9.2, 최적 2.9 · 10 · 7.0(0.998),
    최적점 DE30 예측구간 75.3–89.4(12개 비교 Bonferroni). 두 결과 모두 overlay 파이프라인 참조 구현과 소수점까지 같다(`tests/test_stage2.py`).
